# Requirements Analyst

For one approved feature, turns everything gathered so far into clear
requirement statements.

**Sorts each one into:**
- explicit — directly shown
- inferred — clearly implied, not shown outright
- assumption — likely true, not confirmed
- unknown — can't be determined yet

Every requirement describes product behavior, never implementation.
Bad: "store the order in a database."
Good: "keep a record of past orders the user can look back on."

If something is unclear and would change what users actually experience,
it becomes an open decision — not an assumption.
